# MALCOM-web

Interactive web UI for the RADIANT pipeline. Drives [MALCOMp](../MALCOMp/)'s LLM stages in-process and the [MALCOMj](../MALCOMj/) Gradle transformations as subprocesses, streaming agent I/O to the browser over a WebSocket.

Built on FastAPI + uvicorn, with a Vue 3 + TypeScript frontend bundled by Vite.

---

## Quick Start

```bash
# Standard sibling layout: MALCOM-web/ alongside MALCOMp/ and MALCOMj/
cd MALCOM-web
pip install -r requirements.txt
python -m web
```

Then open <http://localhost:8000>.

The first launch reads the repo-root `config.yaml` (the active case study + the default model from its `models:` map).

```
            store.ts           # Reactive state + WebSocket actions
            types.ts           # Typed wire protocol (mirrors server.py)
            composables/       # useSocket, useResizable
            components/        # Pipeline / Dialogue / Archive panels + parts
            lib/format.ts      # JSON pretty-print + highlight.js
        vite.config.ts     # base=/static/, builds into ../web/static
```

## Frontend (Vue 3 + Vite)

The UI is a Vue 3 + TypeScript single-page app. Vite builds it into
`web/static/` (with `base: /static/`), which is exactly what FastAPI's `/` and
`/static` mount already serve — so the Python side needs no changes.

The built bundle in `web/static/` is committed, so `python -m web` runs the UI
with **no Node.js required**. You only need Node to change the frontend.

```bash
cd frontend
npm install          # once

# Develop with hot-reload (Vite on :5173, proxies /api and /ws to :8000).
# Run the Python server too: from MALCOM-web/, `python -m web`
npm run dev

# Rebuild the committed bundle after changes:
npm run build        # type-checks (vue-tsc) then writes ../web/static/
```

Requires Node.js 18+. The wire protocol lives in `frontend/src/types.ts`; keep
it in sync with `web/server.py` if you add WebSocket message types.

## Locating MALCOMp and MALCOMj

By default MALCOM-web assumes the sibling layout:

```
REMEDIATE/
    MALCOMj/
    MALCOMp/
    MALCOM-web/
```

Override either path with an environment variable:

| Variable | Purpose | Default |
|----------|---------|---------|
| `MALCOMP_DIR` | MALCOMp project root (must be importable as `phases.*`) | `../MALCOMp` |
| `MALCOMJ_DIR` | MALCOMj project root (used to invoke `gradlew` tasks) | `MALCOMP_DIR/../MALCOMj` |

```bash
# PowerShell
$env:MALCOMP_DIR = "C:\path\to\MALCOMp"
$env:MALCOMJ_DIR = "C:\path\to\MALCOMj"
python -m web

# bash
MALCOMP_DIR=/path/to/MALCOMp MALCOMJ_DIR=/path/to/MALCOMj python -m web
```

## How it talks to MALCOMp / MALCOMj

- **MALCOMp** — `bridge.py` adds `MALCOMP_DIR` to `sys.path` and imports the stage classes (`TermExtraction`, `DSLExtraction`, `EMFModelCreation`, `StateMachineExtraction`) directly. Agent I/O is captured by routing pyautogen's `IOStream` through `WebSocketIOStream`.
- **MALCOMj** — Gradle tasks (`runAuvEmfCreation`, `runAuvValidation`, ...) are launched via `subprocess.Popen` with `cwd=MALCOMJ_DIR`. Required prerequisite JSONs are copied from MALCOMp's `output/` into `MALCOMj/src/main/resources/examples/<study>/model/` before each run.

---

## Session persistence

Selected case study, chat history, and stage statuses are persisted to `MALCOMP_DIR/output/.session.json` so they survive a server restart.
